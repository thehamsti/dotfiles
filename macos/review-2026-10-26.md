# macOS dotfiles review

Reviewed the bootstrap, backups, shell integrations, Git/SSH template, owned
tmux scripts, Powerline config, and Neovim Lua configuration. Existing work from
the Homebrew/mise migration was preserved. Full setup and the legacy Nix
uninstaller were not run on this machine.

## Fixes

| Area                  | Finding                                                                                                                                      | Change                                                                                                                                                                                                       |
| --------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Config links          | Repeating `ln -sf` against a directory symlink creates a link inside its target. Fixed `.bak` destinations also collide on later runs.       | All setup links use `link_config.sh`, skip correct links, and move conflicting configs to unique adjacent backup directories. Missing sources leave existing configs intact.                                 |
| Fresh Homebrew setup  | The child installer loaded Homebrew's environment only for itself. Later parent steps could miss mise.                                       | Setup loads `brew shellenv` in the parent and saves the unevaluated command in the login profile. The legacy Nix migration's profile output was corrected too.                                               |
| Powerline             | Setup contained an invalid Python expression, installed into a user pip directory, and tmux hard-coded Python 3.13.                          | Upstream Powerline 2.8.4 runs through mise with a private Python 3.14. tmux uses a shim-aware setup script.                                                                                                  |
| PAM                   | Moving a temporary file into `/etc/pam.d/sudo` preserves its user ownership and mode.                                                        | New Touch ID setup writes `sudo_local` using `install -o root -g wheel -m 644`, preserves custom policy order, and backs up changed local config. Bootstrap also repairs the main file's ownership and mode. |
| sudo sessions         | Setup's credential refresh ended before the lengthy package installation. Defaults setup could leave its background refresh process running. | Bootstrap keeps credentials refreshed across the run; both scripts clean up their refresh processes and temporary files.                                                                                     |
| macOS preferences     | Setup wrote `LSQuarantine=false` and explicitly terminated Terminal, Safari, Mail, and other working apps.                                   | Removed that preference change and limited explicit process restarts to Dock, Finder, and SystemUIServer.                                                                                                    |
| Backups               | Backups were created using the caller's umask, omitted `.zprofile` and the mise/Bun manifests, and stopped after a failed Brew export.       | Private directories/files, unique destinations, additional manifests, and partial-failure reporting after remaining files are saved.                                                                         |
| SSH template          | An old crypto allowlist replaced modern OpenSSH defaults and included the legacy `ssh-rsa` signature algorithm.                              | Use the installed OpenSSH algorithm defaults. Existing `~/.ssh/config` was not changed.                                                                                                                      |
| tmux project sessions | Prefix matching could select a different existing session; dotted directory names produced invalid session names.                            | Exact session matching and valid names for dotted project directories.                                                                                                                                       |
| Shell bootstrap       | Setup/profile integration ignored `ZDOTDIR` and the shims path ignored `XDG_DATA_HOME`.                                                      | Honor those directories when writing Zsh startup files and constructing the mise shims path.                                                                                                                 |

## Existing machine settings requiring a separate action

Read-only checks found `/etc/pam.d/sudo` owned by the current user with mode
`600`, matching the old setup bug. Its contents were not modified during this
review. To repair ownership and permissions alone:

```sh
sudo chown root:wheel /etc/pam.d/sudo
sudo chmod 644 /etc/pam.d/sudo
```

The old script's `com.apple.LaunchServices LSQuarantine` preference is currently
`0`. To restore the first-open prompt preference:

```sh
defaults write com.apple.LaunchServices LSQuarantine -bool true
```

Neither command sequence was applied during the review. New setup uses the
macOS `sudo_local` extension point; it does not remove custom authentication
rules already present in the main `sudo` file.

## Remaining choices

- Consolidate the live shell configuration into tracked files. It still loads
  legacy NVM/Vite runtime paths and many repeated Bun PATH snippets. Reload now
  deduplicates paths, but a smaller startup config would be easier to maintain.
- Narrow `gitignore_global` to OS/editor junk. Rules for `.vscode`, `.zed`,
  `.envrc`, and `dist/` can hide newly added shared project files. These were
  left unchanged because they are a workflow policy choice.
- Make tmux project-session identity directory-aware. Different project roots
  can still have the same basename; changing that policy would rename existing
  session conventions. The project-root selector also uses a space-separated
  root list.
- Resolve the Neovim tsgo server through a project toolchain instead of the
  Vite-specific fallback paths. The owned Lua files parse; plugin installation
  and LSP startup were not exercised.

## Validation and limits

Tests exercise repeated complete setup in temporary homes, conflicting config
backups, missing sources, private and partial backups, generated shell init,
PAM policy ordering and idempotence, modern SSH defaults, and tmux argument
handling. Package installers and privileged operations are mocked; this does
not prove live Touch ID authentication or a fresh-machine Homebrew install.

Powerline's real CLI and configuration lint were checked using the installed
mise tool. Neovim Lua files were compiled without loading plugins. No live
macOS preferences, PAM files, SSH config, or existing tmux sessions were changed.

References: [OpenSSH configuration defaults](https://man.openbsd.org/ssh_config),
[pam_reattach ordering](https://github.com/fabianishere/pam_reattach#usage), and
[upstream Powerline](https://github.com/powerline/powerline). The installed
`/etc/pam.d/sudo_local.template` also documents the persistent local extension.
